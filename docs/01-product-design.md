# VOCAL LISTENING LAB — 全体設計 v0.1

設計日：2026-10-05 JST。対象：`chanwata/vocal-study`。状態：設計提案。実装・配信録音の全件検証・公開は未実施。

## 1. 何を作るか

名演を聴きながら、歌の違いを具体的に説明し、自分の歌や音楽の聴き方へ持ち帰る日本語教材。中心になるのは「この歌の、何が、どう働いているか」という問いである。

基本ループは **聴く → 一つの違いを見つける → 言葉にする → 任意で短く試す → もう一度聴く**。声域や音程の点数を競うのではなく、表現上の選択肢を増やす。

対象者は、歌が好きで、主要な歌手・ジャンル・歌唱表現を体系的に知りたい成人。初心者からアマチュア歌手までを想定する。特定の受け取り手の経験、声域、ジャンルの好みは未指定なので固定しない。歌わない音楽好きやバンドの他パートにも使える内容とする。

### 到達目標

1. 初めて聴く歌について、具体的な区間を示しながら三つの観点で説明できる。
2. 同じ「力強い」「柔らかい」という印象でも、言葉・リズム・音色・録音処理のどこが関わるか仮説を立てられる。
3. 歌手の経歴や文化的背景を、対象曲の聴き方につなげられる。
4. 任意の実験で、一度に一つの条件を変えて比較できる。
5. 録音版や確認できない機材情報を、確定事項と取り違えない。

## 3. 学習の六つの軸

| 軸 | 何を聴くか | 初心者への問い |
|---|---|---|
| リズム | 拍との位置、入り、休符、音を切る位置 | 歌の始まりと終わりは、ドラムのどこにある？ |
| 言葉 | 子音、母音、アクセント、意味のまとまり | 強く聞こえたのは、どの言葉のどの部分？ |
| 旋律 | 音程への入り方、着地、装飾、ビブラート | 音の高さは、すぐ決まる？ 途中で動く？ |
| 声色と強弱 | 明暗、輪郭、息の聞こえ方、音量の推移 | 同じフレーズの中で、声の質感はどこで変わる？ |
| フレーズと関係 | 一息のまとまり、語り、コーラス、伴奏への応答 | 声が引いたあと、誰が続きを話している？ |
| 録音の音 | 近さ、残響、左右、重なり、加工 | 一人の歌として聞くと説明しにくい部分はある？ |

全曲で六項目を埋めさせない。各曲の主役は一つ、補助は二つまで。チェックは学習行動の記録であり、歌唱能力の評価にしない。

## 4. コース構成

初期完成版は14回、各3曲、計42曲案。各回は基本2曲と発展1曲。名人を人数分並べるのではなく、同じ問いに対する異なる答えを比べる。選曲・各回の原稿は[教材・掲載文案](02-editorial-draft.md)に記載。

| ブロック | 回 | 内容 |
|---|---:|---|
| 歌を聴く耳 | 1〜3 | 声の輪郭、言葉と拍、ゴスペルからソウルへの文脈 |
| 表現の動き | 4〜7 | ファンク、親密さ、装飾、声色・声域の変化 |
| 歌と作品 | 8〜11 | ロック、語り、R&B、コーラスと重ね録り |
| 自分へ戻す | 12〜14 | 日本語、加工された声、表現の選択とまとめ |

### 1回の流れ

**15分ルート**：問いを読む1分 → 基本2曲から30〜60秒程度の場面を各3回聴く3〜6分 → 比較とメモ3分 → 任意の短い実験または無発声の観察2〜3分 → 戻って確かめる。時間は目安で、アプリ切替なども考慮する。

**25〜40分ルート**：3曲の全体を聴く → 指定場面を比較 → 人物・録音解説 → 実験 → メモ。全曲全編を3回聴くことを15分の前提にしない。

全コースは短いルートで約3.5時間、深掘りで約6〜9時間の設計目安。14日で歌が完成する、音域が広がる、といった効果は約束しない。

実装時には曲の所属回を一つに固定し、比較ページから同じ曲へ戻れるようにする。新しい曲を足しても既存IDは変えない。

### レッスン内の情報順

1. 今日の問いと所要時間。
2. 基本2曲の要点と再生導線。
3. 各曲の「聴く場所 → 三つの聴き方 → 短い解説」。最初の基本曲は展開し、残りは折りたたむ。
4. 比較の問い、必要なら実験。
5. メモ、学習済み、次へ。

人物・文化史・機材・出典は各曲から開ける。歌唱法の専門用語を知らなくても最初の行動が分かるようにする。

### iPhone優先の表示

- 本文16px以上、入力欄16px以上、行間1.8程度。主要操作は高さ44px以上を目標とする。
- 幅320／375／390／430pxを検証。本文は一列、画面全体の横スクロールなし。
- 画面下は「曲へ・比較・メモ」の短い補助移動。セーフエリア分を確保し、キーボード表示で入力欄を覆わない。
- 目次は開閉式。全14回が本文より先に長く出ない。
- 上部に巨大なプレイリストを置かず、必要な曲の位置でプレーヤーを読み込む。
- 保存操作は常設の短い状態表示とデータ画面へ整理する。
- PCは目次＋本文の二列を基本に、十分な幅がある場合だけ再生補助欄を出す。
- キーボード操作、フォーカス表示、見出し階層、画面読み上げのラベルを用意。色だけで状態を表さない。

### 見た目

姉妹教材と分かる落ち着いた書籍風の構成を継承する。vocal版は濃いプラム系の見出し、暖かな白、控えめな珊瑚色を候補とし、文字コントラストは実装時に確認。歌手写真やジャケットの転載を前提にせず、文字と簡潔なリズム・音の図で成立させる。

## 6. Spotifyと録音版

1. `recordingId`を内部の主キーにする。Spotify ID、プレイリストの順番、曲名を主キーにしない。
2. 各曲にアーティスト、実際の歌唱者、アルバム、スタジオ／ライブ、原リリース年、配信版名、確認日を持つ。必要な曲ではモノ／ステレオ、ミックス違いも明記する。
3. 曲別の埋め込みと「この録音を開く」、プレイリストの「まとめて聴く」を両方置く。埋め込み内部のSpotifyロゴの動作は変更しない。
4. `playlist`は未設定を許容。確認済みの曲リンクだけでも教材を使える。未設定なら空の埋め込み・架空ID・bass版プレイリストを出さない。
5. プレイリスト設定後は42件のIDと順序を教材マニフェストと照合。差異を曲IDで記録し、曲番号による特殊処理を作らない。
6. 発売年と再発年を混同しない。ライブ版をスタジオ版の分析に当てない。検索リンクは「検索」と明示し、「指定録音」と表示しない。
7. 再生不可や短い試聴でも本文を読める。利用条件による制限を説明し、Spotifyアプリへのリンクを残す。フル再生は保証しない。
8. 公開済み楽曲の自動ループ、速度変更、キー変更、録音保存は初期版に含めない。場面の目印を文章で指定し、秒数は対象版を聴いてから補助表示する。

公式埋め込みの範囲は[Spotify資料](04-evidence-and-decisions.md)に基づく。Spotifyアカウント連携やプレイリスト作成は別作業。GitHubへのアクセスだけで実行できるとは扱わない。

## 7. 保存とプライバシー

- `localStorage`キーは`vocal-listening-lab-v1`。`bass-listening-lab-v1`を読み書きしない。同じGitHub Pagesオリジンにある別リポジトリと混ざることを防ぐ。
- 保存対象：回の学習済み、曲の確認済み、回・曲・比較のメモ、最後の回、学習モード。音声ファイルは保存しない。
- 自動保存が成功したときだけ「この端末に保存済み」。失敗時は入力をメモリに保持し、バックアップへ進める。
- 初回とデータ画面で「この端末・このブラウザに保存。端末間の自動同期なし。ブラウザのデータ削除などで消えることがある」と説明。
- JSONは復元可能な全データ、TXTは読むためのメモ。用途を分ける。
- 復元はファイル種別・形式・教材ID・版・型・IDを確認し、件数を表示してから置き換える。処理が失敗したら現データを維持する。
- 壊れた保存値を起動時に検出したら、勝手に空データで上書きしない。原文の書き出しと復旧の選択肢を出す。
- 複数タブの別項目編集は直近データと統合。同じメモの衝突は警告し、編集中の文字を自動で消さない。
- アカウント、音声のクラウド送信、行動分析は初期版に入れない。外部Spotify埋め込みは読み込み操作後に接続する。

## 8. 声を使う課題の設計

全課題に「声を出さずにできる代替」を用意する。原曲キー、原曲の音量、声色の一致は要求しない。高い声、強い叫び、歪みの再現は聴く課題として扱い、強く喉を押す等の手順を書かない。

短い案内文：「出しやすい高さと無理のない音量で。痛み、声がれ、出しづらさを感じたら歌うのをやめ、今日は聴く課題に切り替えてください。症状が続く・繰り返す場合は耳鼻咽喉科などへ相談してください。」これは[NIDCDの声のケア](https://www.nidcd.nih.gov/health/taking-care-your-voice)を踏まえた教材上の配慮であり、診断や治療の機能は設けない。

「ミックスボイス」「支え」などは流派や用法の差を示す。完成音源だけから喉頭・声帯の動作、健康状態、本人の意図を断定しない。

## 10. 完成判定

作品としての完成条件は「開く → 選ぶ → 指定録音を聴く → 比較する → メモが残る → 再訪して続けられる」がiPhoneで成立すること。42曲の埋め込みがあるだけでは完成扱いにしない。内容・録音照合・保存・操作の具体条件は[実装計画](03-implementation-plan.md)に定義する。
